===============================================================================
PRESENTATION GUIDE: How to Show Your Teacher
===============================================================================

Step 1: Open your Terminal and Start the Container
First, ensure your Docker container is running and open an interactive shell inside it:

  docker start polito-os161
  docker exec -it polito-os161 /bin/bash

Step 2: Navigate to the Compiled Kernel
Once inside the container, navigate to the root directory where the compiled OS/161 kernel executable is located:

  cd /home/os161user/os161/root

Step 3: Run the Tests Live
Now, you can execute the three assignment tests for your teacher to prove they work without deadlocks or race conditions.

To show Part 1 (Math Problem):

  sys161 kernel "1a;q"

Point out to your teacher that the final sum is exactly 10,000 and no updates were lost thanks to the lock.

To show Part 2 (Producer/Consumer):

  sys161 kernel "1b;q"

Point out that exactly 200 items were produced and 200 were consumed successfully.

To show Part 3 (Bar Synchronization):

  sys161 kernel "1c;q"

Point out that all 8 customers were served by the 2 bartenders, and the program exited cleanly without hanging.

Step 4: Show the Code
If your teacher asks to see the actual code you wrote, you can display the files directly in the terminal:

  For the Lock/CV implementation:  cat /home/os161user/os161/src/kern/thread/synch.c
  For the Math code:               cat /home/os161user/os161/src/kern/asst1/math.c
  For Producer/Consumer code:      cat /home/os161user/os161/src/kern/asst1/producerconsumer.c
  For Bar code:                    cat /home/os161user/os161/src/kern/asst1/bar.c

Step 5: Explain Your Logic
Open the solve1.md, solve2.md, and solve3.md files (in the CSE-3201-OS/OS161/ folder) as reference:

  - math.c uses a Lock for mutual exclusion on the shared counter.
  - producerconsumer.c uses a Circular Array with Condition Variables (not_full, not_empty).
  - bar.c uses a Ticket Queue with Condition Variables for FIFO ordering.
  - synch.c implements the lock and CV primitives using wchan and spinlocks.

Note: The original OS/161 had empty stub implementations for locks and CVs.
The synch.c file provides the actual working implementation that all three
solutions depend on.
